# 提案 0001: まひ状態の追加(記入例)

> これは仕様ループの記入例。新規プロジェクトでは削除またはコピーして使う。

## なぜ
このカードプールで状態異常が頻出し、エンジンが未対応だと合法手判定が誤る。

## 影響範囲
- ADDED: 状態異常の概念、まひのロジック
- MODIFIED: get_legal_actions(行動制限)、apply_turn_end(回復処理)

## 種別判定
決定的(同じ状態 → 同じ合法手)。仕様ループで進める。

## 設計案
> spec が承認されてから埋める(仕様が決まる前に設計しない)。書式は `.claude/rules/design-rules.md`。

- 採る案: 状態異常を `src/engine/status.py` に新規で置き、`get_legal_actions` から参照する。
  状態は `battle_state` が持ち、engine 内の純関数で受け渡す。
- 採らなかった案: 各行動クラスに「まひなら弾く」判定を持たせる案 — 合法手の定義が
  行動ごとに散り、engine と agent で二重管理になる(不変条件:依存方向)。
- 影響する層: engine のみ。agent / eval には触らない。依存方向は崩さない。
- ADR: 不要。層の割り当ても契約も既存の枠内で、他の change に波及しないため。
