# 探索のルール(非決定的部分)

## いつ使うか

出力が指標でしか評価できないとき(勝率・精度・速度・品質スコア)。
強さ・良さを spec/test で縛ろうとしない。

## 単位:experiments/NNNN-xxx/

- `hypothesis.md`:仮説 / 測り方(指標・試行数・シード) / 中止条件。
- `config.yaml`:変更したパラメータ。
- `result.md`:指標の実測値 + 考察。**シードと依存を固定した再現可能な条件でのみ記録**。

## 規律

- 1実験 = 1つの変数変更。何を変えたら指標がどう動いたかを追えること。
- baseline を最初に作り、すべての実験は「baseline をどれだけ上回ったか」で測る。
- 失敗実験も result を残す(なぜダメだったかが次の仮説になる)。
- 「残す」はリポジトリのフォルダに置くことで、**git に上げるかは別**。git に上げる範囲の正本は
  `gitignore.template`(プロジェクト開始時に `.gitignore` になる)で、既定では `experiments/` を
  追跡しない(ローカルの記録)。チームで result を共有するときは該当行を消す。

## hypothesis.md テンプレ

```markdown
# 仮説
<X を変えると指標 Y がこう動くはず>
## 測り方
<対戦相手/データ、試行数、シード、見る指標>
## 中止条件
<予算超過/明確な悪化なら中止して何に戻すか>
```
