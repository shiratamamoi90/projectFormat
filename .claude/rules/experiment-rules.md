# 探索のルール(非決定的な論点の決め方)

## いつ使うか

出力が指標でしか評価できないとき(勝率・精度・速度・品質スコア)。
強さ・良さを spec/test で縛ろうとしない。

**非決定的な論点も、決定的な論点と同じ入れ物(`decisions/`)に置く。** 違うのは
**決め方が計測になる**ことだけ。論点フォルダの置き方・種別タグ・確定手順は
@doc-rules.md「確定の流れ」が正本(ここに書き写さない)。

## 単位:`decisions/undecided/NNNN-<論点名>/`

決定的な論点は `topic.md` だけを持つ。**非決定的な論点はこれに2つ足す。**

- `topic.md`:何を決めるか / 案 / **測り方**(指標・試行数・シード)/ 中止条件 / 現在の考え。
  冒頭のタグは `種別: 非決定的`。
- `config.yaml`:変更したパラメータ。
- `result.md`:指標の実測値 + 考察。**シードと依存を固定した再現可能な条件でのみ記録**。

決まったら `decisions/decided/` へ移す。計測ファイルは論点フォルダに残す — **測った過程は消さない**。
決めた値そのものは config として実装側に置く(@impl-rules.md「ハードコード禁止」)。
**探索設定を文書に書き写さない** — config を見れば分かる。論点に残すのは「なぜその値か」。

## 規律

- **1論点 = 1つの変数変更。** 何を変えたら指標がどう動いたかを追えること。
  複数の変数を振りたくなったら、論点を分ける。
- **baseline を最初に作り、すべての計測は「baseline をどれだけ上回ったか」で測る。**
  baseline は文書ではなく `src/` の実装として置く(どんな baseline があるかはコードを見れば分かる)。
  **一度作った baseline は固定する** — 変えると過去の計測と比較できなくなる。改良したいときは
  別名で追加し、どちらと比べたかを `result.md` に書く。
- **測って捨てた案も `却下した案` に残す**(なぜダメだったかが次の論点になる)。
  結論が出ないまま止めた論点は `undecided/` に置いたままにする。決まっていないものを
  決まったように見せない。
- `decisions/` は git 追跡対象。**測定結果はチームで共有される前提**で書く
  (生データ・個人情報を貼らない。@security-rules.md「機密情報」)。

## 測り方の書式(topic.md の中)

```markdown
## 測り方
<対戦相手 / データ、試行数、シード、見る指標>

## 中止条件
<予算超過 / 明確な悪化なら中止して何に戻すか>
```
