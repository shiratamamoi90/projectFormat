---
name: tidy
description: docs/ を LLM Wiki として意味を変えずに整理し直す(分割・統合・移動・相互リンク・目録と全体像の更新・点検)。規範の差分 0 を機械で確かめて終える。
---

引数 $ARGUMENTS があれば整理の範囲(例: `requirements/`)として扱い、無ければ `docs/` 全体を見る。
運用の正本は @.claude/rules/doc-rules.md「wiki の運用」(ここに書き写さない)。

**目的は人間が把握しやすい状態に保つこと。** 決まったことが増えるたびに、ページの切り方・並び・
リンク・要約を作り直してよい。ただし**規範の意味は1文字も変えない**(変えるのは `/decide` だけ)。

前提確認(**欠けたら停止する。この skill の停止条件**):
- 作業ツリーに未コミットの変更が `docs/` に無いこと(`git status docs/`)。比較の基準を HEAD に置くため。
  あれば、それが何かを人間に確認してから始める。

手順:
1. **点検する**(Karpathy の LLM Wiki の lint):
   - `scripts/validate.sh` の「索引とリンク」「規範ページの由来」「作業記録の書式」の NG
   - ページ同士の食い違い、新しい決定で古くなった説明、ページの無い概念、張られていない相互リンク
   - 1ページに要件が詰め込まれすぎている / 細かく割れすぎている
2. **整理案を人間に示す**(移す・割る・まとめる・リンクを張る・説明を書き直す・目録の分類を変える)。
3. 承認された範囲で整理する。**規範ページの箇条書き・表の行・シナリオは一字一句そのまま移す**
   (直したい表現があっても直さない — 直すなら論点を開く)。説明ページと散文は書き直してよい。
4. `docs/index.md` と `docs/overview.md` を整理後の構成に合わせる。
5. **`scripts/validate.sh --normative-diff HEAD` が「規範の差分なし」を返すことを確かめる。**
   差分が出たら、その変更を元に戻す(規範を変えたいなら `/new-topic` へ)。
6. `scripts/validate.sh` を実行し、`docs/log.md` に追記して報告する
   (`## [YYYY-MM-DD] tidy | <何を整理したか>`、移したページの旧→新を箇条書きで)。

食い違いや古くなった**規範**を見つけた場合は、直さずに `/new-topic` で論点を開く。
**テストも実装も書かない**(@.claude/rules/test-rules.md「着手の許可」)。
